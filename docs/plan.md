# 『とりあえず勇者』実装計画書 v0.1

## 1. 技術スタック

| 役割 | 使うもの | 選んだ理由 |
|------|---------|-----------|
| 画面 | React + TypeScript（Vite） | 前回の課題で使った経験がある |
| データベース・ログイン | Supabase（PostgreSQL・匿名ログイン） | 認証・DB・リアルタイムが1つにまとまっている |
| リアルタイム（焚き火） | Supabase Realtime Presence | 「今この部屋にいる人の名簿」を全員で共有する機能。サーバーを自作しなくてよい |
| 公開 | Vercel | GitHubにプッシュすると自動で公開URLが更新される |
| 見た目 | 素のCSS（MVP） | MVPは動作確認が目的。デザインは後で決める |

## 2. ディレクトリ構成

```
toriaezu-hero/
├─ docs/                    仕様書・計画書
├─ supabase/
│  └─ migrations/           DBのテーブル・関数を作るSQL（順番に番号をつける）
├─ src/
│  ├─ main.tsx              アプリの入り口
│  ├─ App.tsx               画面全体の組み立て（焚き火 / タスクの2エリア）
│  ├─ lib/
│  │  └─ supabase.ts        Supabaseにつなぐ設定（1か所だけ）
│  ├─ config/
│  │  └─ rewards.ts         報酬の数値・宝箱ランクのしきい値
│  ├─ types/                データの型（quests, quest_sessions など）
│  ├─ components/           どの機能でも使う部品（ダイアログなど）
│  ├─ features/             機能ごとのまとまり
│  │  ├─ auth/              匿名ログイン・表示名の入力
│  │  ├─ quests/            クエストに挑戦・予約・クエスト一覧
│  │  ├─ session/           挑戦中のタイマー・帰還モーダル
│  │  ├─ campfire/          焚き火（オンライン・最近来た人）
│  │  └─ status/            XP・レベル表示
│  └─ styles/               CSS
├─ .env.local               SupabaseのURLとキー（GitHubには上げない）
└─ package.json
```

`features/` の中は、それぞれ「画面の部品（components）」と「処理（hooks）」に分ける。

## 4. バージョン管理
- ベータ版として `0.y.z` 形式。MVP完成を `0.1.0` とする。
- 変更のたびに、変更点・ファイルの役割・処理の方法・理由を説明する。

## 5. Supabase の権限ルール（重要）
このプロジェクトは2026年5月以降に作ったため、新しいテーブルや関数は **作っただけでは画面側から使えない**（自動で権限が付かない）。
テーブルや関数を作るSQLには、必ず次の2つをセットで書く。

1. `grant`：どの操作（select / insert / update / delete / execute）を許すか
2. RLS ポリシー：どの行を許すか（基本は「自分の行だけ」）

`grant` を忘れると、ブラウザに `403` エラーが出る。
