# 『とりあえず勇者』実装計画書 v0.1

## 1. 技術スタック

| 役割 | 使うもの | 選んだ理由 |
|------|---------|-----------|
| 画面 | React + TypeScript（Vite） | 前回の課題で使った経験がある |
| データベース・ログイン | Supabase（PostgreSQL・匿名ログイン） | 認証・DB・リアルタイムが1つにまとまっている |
| リアルタイム（焚き火） | Supabase Realtime Presence | 「今この部屋にいる人の名簿」を全員で共有する機能。サーバーを自作しなくてよい |
| 公開 | Vercel | GitHubにプッシュすると自動で公開URLが更新される |
| 見た目 | 素のCSS（MVP） | MVPは動作確認が目的。デザインは後で決める |

## 2. ディレクトリ構成

```
toriaezu-hero/
├─ docs/                    仕様書・計画書
├─ supabase/
│  └─ migrations/           DBのテーブル・関数を作るSQL（順番に番号をつける）
├─ src/
│  ├─ main.tsx              アプリの入り口
│  ├─ App.tsx               画面全体の組み立て（焚き火 / タスクの2エリア）
│  ├─ lib/
│  │  └─ supabase.ts        Supabaseにつなぐ設定（1か所だけ）
│  ├─ config/
│  │  └─ rewards.ts         報酬の数値・宝箱ランクのしきい値
│  ├─ types/                データの型（tasks, work_sessions など）
│  ├─ features/             機能ごとのまとまり
│  │  ├─ auth/              匿名ログイン・表示名の入力
│  │  ├─ tasks/             タスクの追加・一覧・完了・見送り
│  │  ├─ expedition/        遠征タイマー・帰還モーダル
│  │  ├─ campfire/          焚き火（同席者・ゴースト）
│  │  └─ status/            XP・レベル・ゴールド表示
│  └─ styles/               CSS
├─ .env.local               SupabaseのURLとキー（GitHubには上げない）
└─ package.json
```

`features/` の中は、それぞれ「画面の部品（components）」と「処理（hooks）」に分ける。

## 3. 実装ステップ

各ステップの終わりに、ブラウザで動作確認してからプッシュする。

| # | ステップ | 終わったときにできること |
|---|---------|------------------------|
| 0 | 準備：GitHubリポジトリ・Supabaseプロジェクト・Vercelを用意 | — |
| 1 | Viteで雛形を作り、Supabaseにつなぎ、Vercelで公開 | 公開URLで「Hello」が見える（週次レポート用のURLを最初に確保） |
| 2 | 匿名ログイン＋表示名の入力、`profiles` テーブル | 名前を入れるとログイン状態になり、再読み込みしても保たれる |
| 3 | `tasks` テーブル＋タスクの追加・一覧・完了・見送り | タスクを管理できる |
| 4 | `work_sessions` テーブル＋遠征タイマー（開始時刻方式） | 出撃→1分で表示が変わる→再読み込みしても続きから数える→2時間で自動帰還 |
| 5 | 帰還モーダル＋報酬を計算するDB関数 | 日誌を書くと宝箱が開き、XP・ゴールドが増える |
| 6 | 焚き火（Realtime Presence） | 別のブラウザで出撃すると、もう片方の焚き火に表示される |
| 7 | ゴースト（DB関数で取得） | 前日の同時間帯の作業者が半透明で表示される |
| 8 | 応援（`cheers`） | 帰還すると同席者の薪が増える |
| 9 | 全体の動作確認・バグ修正 → MVP完成 | 2つのブラウザで一連の流れが通る |

### MVPのあと（優先順の案）
1. 見た目・演出（焚き火のイラスト、宝箱の演出）
2. ご褒美交換所
3. 冒険日誌・討伐図鑑
4. 拠点強化
5. フェーズ2（クイック出撃・合図クエスト）

## 4. バージョン管理
- ベータ版として `0.y.z` 形式。MVP完成を `0.1.0` とする。
- 変更のたびに、変更点・ファイルの役割・処理の方法・理由を説明する。
