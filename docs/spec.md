# 『とりあえず勇者』仕様書 v0.2（MVP版）

元の企画書（Geminiとの相談版）を、MVPで作る範囲に絞って整理したもの。
変更点は「元案からの変更」に理由つきでまとめている。

---

## 1. コンセプト

- **アプリ名：** とりあえず勇者（旧仮称：1分勇者）
- **キャッチフレーズ：** 「『あとでやる』を『とりあえずやる』に変える冒険」
- **ゲームの核：** ボスを倒さなくていい。1発殴るだけで経験値がもらえるRPG

### 設計の4原則（変更なし）
1. **作業興奮：** 完了ではなく「1分の着手」で報酬を確定させる。1分経過時に操作を求めない。
2. **無言のボディ・ダブリング：** チャットなし。焚き火の周りに「今いる人」と「ゴースト」を表示する。
3. **ペナルティゼロ：** レベルダウン・記録リセット・没収なし。
4. **良心に訴える：** よそ見検知はしない。1行日誌・応援・正直スライダーで嘘をつきにくくする。

---

## 2. 用語

| 用語 | 意味 | 旧用語 |
|------|------|--------|
| クエスト | やること（作業）の種類。名前が同じなら同じクエスト | タスク・モンスター |
| クエストに挑戦 | タイマーを動かして作業を始めること | 出撃・遠征 |
| 挑戦中 | タイマーが動いている状態 | 遠征中 |
| 帰還 | 挑戦を終えてキャンプに戻ること | （同じ） |
| クエストを予約 | その日（または後日）にやるクエストを決めておくこと | （新規） |
| 見送ったクエスト | 予約した日に挑戦しなかったクエスト | （新規） |

## 3. MVPの範囲

MVPの目的は「主要な機能が動くことの確認」。見た目・演出・細部は後回し。

### MVPで作る
| # | 機能 | 内容 |
|---|------|------|
| 1 | ゲストログイン | Supabaseの匿名ログイン。初回に表示名だけ入力 |
| 2 | クエストに挑戦 | ボタン → クエスト名を入力（過去のクエストから選択も可）→「挑戦！」でタイマー開始 |
| 3 | クエストを予約 | クエスト名・日付・きっかけ（時刻 or 合図、任意）を決める |
| 4 | クエスト一覧 | メニューから開く。過去のクエストから再挑戦・予約・ピン留め。予約中・見送ったクエストも見られる |
| 5 | タイマー | 1分で先制攻撃成功 → 自動で追撃 → 手動帰還 / 2時間で自動帰還 |
| 6 | 帰還モーダル | 1行日誌（必須）、正直スライダー（自動帰還時）、報酬受け取り |
| 7 | 焚き火（同席） | 今挑戦中のユーザーを表示（名前・クエスト名） |
| 8 | ゴースト | 前日の同じ時間帯に挑戦していた人を、区別できる形で表示 |
| 9 | 応援（薪） | 帰還時、同席していた人へ自動で薪を1本送る |
| 10 | ステータス | XP・レベル・ゴールド・受け取った薪の数を表示 |

### MVPでは作らない（後回し）
- 拠点強化（テント・装備・ペットの見た目）
- ご褒美交換所（現実のご褒美チケット）
- 冒険日誌・討伐図鑑の閲覧画面
- ドット絵・アニメーションなどの演出
- メール / Google認証（匿名ユーザーをあとから本登録に切り替える）
- 予約時刻の通知
- クエストの名前変更・削除

## 4. 元案からの変更

| 変更 | 理由 |
|------|------|
| 「タスクを登録して一覧から出撃」ではなく「挑戦ボタン → 名前を入力 → 挑戦！」にした | 着手までの手順を最短にするため。登録という準備作業自体が「後回し」の原因になる |
| 「討伐完了」「今日は見送る」ボタンをなくした | クエストは「完了させるもの」ではなく「1分でも触れたら勝ち」のもの。毎回の挑戦が1回の勝利になる |
| クエスト一覧は「過去に挑戦・予約したクエストの種類」にした | 同じ作業を繰り返すときに、入力なしで再挑戦・予約できるようにするため |
| 予約機能を追加し、予約日に挑戦しなかったら「見送ったクエスト」にする | 「いつやるか」を先に決めると着手しやすくなる（If-Thenプランニング）。フェーズ2の合図クエストを予約の「合図」として前倒しした |
| 見送ったクエストは印が付くだけで罰なし。そこから予約し直せる | 原則3（ペナルティゼロ）のため |
| ゴーストは半透明＋「〇時間前」表示で、本物の同席者と区別する | 本物のように見せると「サクラだった」と信頼を失う。原則4と矛盾するため |
| 報酬の大部分は「1分の着手」で確定し、時間による差は宝箱のランクだけにする | 時間に比例して報酬が増えると、短く正直に申告した人が損をするため |
| 報酬・時刻・集計はDB側の関数で計算する | 画面側（ブラウザ）で計算すると、自由に書き換えられてしまうため |

## 5. 画面とその流れ

### メニュー
- **キャンプ**（ホーム）と **クエスト一覧** の2つ。

### キャンプ（ホーム）
- 焚き火エリア（スマホ：上 / PC：左）：ステータス、挑戦中のタイマー、帰還結果、焚き火
- クエストエリア（スマホ：下 / PC：右）：
  - `[クエストに挑戦]` `[クエストを予約]` の2つの大きなボタン
  - **今日の予約クエスト**：各予約に `[挑戦！]`。達成したら「達成」の印
  - **ピン留めクエスト**：タップすると名前が入った状態で挑戦ダイアログが開く（いきなり始まらない）

### クエストに挑戦（ダイアログ）
1. 「何に挑戦する？」にクエスト名を入力（または「最近のクエスト」をタップ）
2. `[挑戦！]` でタイマー開始

### クエストを予約（ダイアログ）
1. クエスト名（入力 or 最近のクエストから選択）
2. 日付（今日以降）
3. きっかけ（任意）：`決めない` / `時刻`（例 21:00）/ `合図`（例 お風呂から上がったら）
4. `[予約する]`

### クエスト一覧（ページ）
- **予約中（明日以降）**：`[取り消す]`
- **見送ったクエスト**：`[予約し直す]`
- **すべてのクエスト**（ピン留めが先頭）：挑戦回数・合計時間、`[挑戦]` `[予約]` `[ピン留め / ピンを外す]`

---

## 6. 予約のルール
- 予約した日に、そのクエストに **1分以上** 挑戦したら「達成」。
  - 予約カードの `[挑戦！]` から始めても、名前を入力して始めても、同じクエストなら達成になる。
  - 1分未満で帰還した場合は未達成のまま（その日のうちなら、もう一度挑戦できる）。
- 予約日が過ぎても未達成なら「見送ったクエスト」。印が付くだけで、XP・ゴールドなどは減らない。
- 時刻・合図は「目安」。時刻を過ぎても見送りにはならない（その日のうちなら達成できる）。
- 「今日」は利用者の端末の日付で判断する。

---

## 7. タイマーの仕様

### 基本の考え方
タイマーは「1秒ごとに数える」のではなく、**サーバーで記録した開始時刻と今の時刻の差** で経過時間を出す。
スマホで画面を伏せてブラウザが止まっても、開いた瞬間に正しい経過時間が出る。
端末の時計がずれていても表示が記録と食い違わないよう、起動時と挑戦開始時にサーバーへ時刻を聞き、
ずれを差し引いて表示する（`src/lib/serverClock.ts`）。

### 状態
| 状態 | 経過時間 | 画面 |
|------|---------|------|
| 挑戦中 | 0:00〜0:59 | カウントアップ |
| 追撃コンボ中 | 1:00〜1:59:59 | 1分到達時は静かに表示が変わるだけ（音・モーダルなし）。宝箱のランクが上がっていく |
| 帰還（手動） | 任意 | 「キャンプに帰還する」で帰還モーダル |
| 自動帰還 | 2:00:00 | 2時間で自動帰還。画面を閉じていた場合も記録は2時間で止まる |

- 挑戦中のクエストは1人1つまで。
- 1分未満で帰還した場合は報酬なし（記録は残す）。罰ではなく、宝箱が出ていないだけ。

### 宝箱のランク（暫定値・あとで調整）
| 作業時間（申告後） | ランク |
|-----------|-------|
| 1分〜29分 | 木 |
| 30分〜59分 | 銀 |
| 60分〜 | 金 |

---

## 8. 帰還モーダルの仕様（ステップ5）

1. **正直スライダー（自動帰還時のみ）**
   - 選択肢：`1〜15分` `30分` `1時間` `2時間そのまま`
   - 短く申告した場合は「誠実な冒険者ボーナス」として薪+1（ゴールドやXPは増やさない）
2. **1行日誌（必須・1〜50文字）**
   - 入力するまで「宝箱を開ける！」ボタンは押せない
3. **報酬**
   - 基本報酬（1分達成で確定）：XP・ゴールド
   - 宝箱のランクに応じたボーナス
   - 同席していた人へ薪を1本ずつ自動送信

報酬の具体的な数値は `src/config/rewards.ts` にまとめ、あとで調整する。

## 9. データモデル

```
profiles（ユーザー情報。Supabaseの認証ユーザーと1対1）
  id, name, avatar_type, xp, gold, firewood, created_at, last_active_at

quests（クエストの種類。名前はユーザーごとに重複なし）
  id, user_id, title, is_pinned, total_duration_sec, attempt_count, last_attempted_at, created_at

quest_reservations（予約）
  id, user_id, quest_id, scheduled_date, scheduled_time（任意）, trigger_text（任意）,
  fulfilled_at（達成時刻）, fulfilled_session_id, created_at
  ※ 時刻と合図はどちらか一方まで
  ※「見送った」は列で持たず「予約日が過ぎて未達成」で判定する

quest_sessions（1回ごとの挑戦の記録）
  id, user_id, quest_id, reservation_id, started_at, ended_at,
  recorded_duration_sec, declared_duration_sec, is_auto_returned,
  memo_log, reward_rarity, earned_xp, earned_gold, claimed_at

cheers（薪・応援の記録）※ステップ8
  id, from_user_id, to_user_id, session_id, created_at
```

- 画面側からできるのは「読む」「ピン留めの切り替え」「未達成の予約の取り消し」だけ。
  挑戦・帰還・予約はDB関数（`start_quest` / `end_quest` / `reserve_quest`）を通す。
- ゴーストは `quest_sessions` から「ちょうど24時間前の前後1時間に開始した、他人の挑戦」を取り出して作る。
- 他人のデータは直接読めないようにし（RLS）、ゴースト用には必要な項目だけを返す関数を用意する。

### 注意点
Supabaseの匿名ログインには、同じIPアドレスからの回数制限（初期設定で1時間あたり30回）がある。
発表で大勢が同じ学内Wi-Fiから一斉にログインすると、上限に当たる可能性がある。ダッシュボードで変更できるので、発表前に確認する。
